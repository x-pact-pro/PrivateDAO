## Scope

PrivateDAO has two deliberately separate product surfaces:

1. **Commercial organizational products**: six products executed through the shared Kernel and Provider Gateway boundary.
2. **Agent Exchange**: an external-agent marketplace and MCP/A2A service, deployed independently through its Lambda workflow.

Agent Exchange is not counted as a seventh commercial product and is not used as evidence for organizational product execution.

## Commercial execution boundary

```text
Product UI / API
  -> Product capability binding
  -> Protocol workflow
  -> PrivateDAO Kernel
  -> Provider Gateway
  -> Family adapter
  -> Network adapter
  -> Provider / wallet / RPC
  -> Testnet or production network
  -> Receipt / reconciliation / evidence artifact
```

## Agent Exchange boundary

Agent Exchange is isolated under:

- `integrations/agent-exchange-lambda/`
- production endpoint: `https://agents.privatedao.org`
- MCP endpoint: `https://agents.privatedao.org/mcp`

Its technical surface is MCP/A2A/Agent Card based and its payment rail is separate from the organizational network matrix. Agent Exchange health or service discovery does not count as proof of Payroll, Treasury, Governance, Auction, or Verification execution on a target network.

## Security and release controls

- fail-closed production Kernel Gateway authentication
- same-origin validation for browser execution
- explicit production CORS configuration

- Testnet-only guards for the funded E2E runners
- broadcast disabled by default for sensitive network paths
- sanitized external-provider and signer errors
- tracked-secret checks
- product gateway boundary checks
- Agent Exchange MCP protocol checks

## Reviewer rule

Do not infer E2E completion from a registry row, capability declaration, RPC health, contract deployment, or a preparation result alone. Use the evidence index and follow the linked artifact.
