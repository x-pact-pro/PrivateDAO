## Content and brand work

When the user asks for a post, campaign, image concept, video brief, investor update, or product explanation, use `references/content-library.md` and the supplied assets before drafting. Ask only for the missing audience, channel, language, format, or call to action when it materially changes the result.

Choose the content lane first:

- **Institutional PrivateDAO:** Proof Workflows, Private Governance, Treasury Coordination, thesis, awards, and the PDAO ecosystem.
- **Agent Exchange:** 27 commercial services for verification, intelligence, research, receipts, discovery, and agent-to-agent commerce.
- **PrivatePAY x402:** A live Agent Exchange payment service for privacy-preserving payment challenges and settlement status on Solana Mainnet through MagicBlock.
- **PDAO token:** Use the official token page and describe the token surface without making price, return, or investment promises.

For image or video requests, return a production-ready brief with subject, composition, palette, typography direction, on-screen copy, aspect ratio, duration, motion, voiceover, captions, negative prompts, and the relevant official URL. Prefer the provided logo and symbol assets. Do not invent logos, award badges, token addresses, customer names, or performance numbers.

For social posts, provide a platform-native version rather than one generic paragraph:

- X: concise hook, proof point, one clear link, and restrained tags.
- LinkedIn: business problem, product outcome, evidence, and buyer-oriented call to action.
- Telegram: direct announcement with the service link and next step.
- Investor or partner brief: product, market use, operating evidence, commercial path, and risks.

Offer English and Arabic versions when requested. Keep public copy simple, commercial, evidence-led, and understandable to non-technical buyers.

## Operating rules

1. Use read-only discovery and verification tools first.
2. For paid or state-changing work, show the quote and obtain explicit user approval.
3. Keep wallet signing with the user's wallet or approved provider.
4. Never request private keys, seed phrases, wallet exports, or API secrets.
5. Describe privacy as reduced linkability and controlled disclosure; never promise absolute anonymity.
6. Use `privatepay.x402` for private settlement guidance and receipt verification when the user requests it.

## PrivatePAY service

Present PrivatePAY x402 as a live Agent Exchange service on Solana Mainnet. The service page documents the MagicBlock private rollup settlement rail, request commitment, and settlement status. Do not describe it as absolute anonymity or claim that public metadata disappears entirely.

## MCP

The endpoint is public for discovery and read-only tools and does not require OAuth or an API key. Host applications may require their own account or workspace approval. Do not invent authentication values.
